    Specification

    worldarray is built to this document. Sections 1 to 5 are also the README; every statement under "Behaviour" and "Tests" is something a test pins. Code that is not needed to make a statement here true does not go in; a behaviour not stated here is not implemented without adding the statement first.

    Draft 3, 2026-10-22. Written from a reading of every existing reader in David Ackerman's repos and the answers of the chunkmirage, cellmap-flow, cellmap-analyze, mesh-n-bone, CineMap, liconn-err, registration-station, salamander and cellmap-analyze-scripts sessions; the write side (0.2) and the grid side (0.3) were added on 2026-10-22 from the five writer sessions' answers and the line census in section 6. Decisions still open are in section 7. Version map: 0.1 reads (Behaviours 1 to 9); 0.2 metadata and placed creation (10 to 16); 0.3 grids and blocks (17 to 19). Nothing in 0.2 or 0.3 changes a 0.1 behaviour.

    0. Why this exists

    Seven readers across those repos open the same zarr v2, zarr v3, N5 and precomputed volumes through tensorstore and each parses the OME-NGFF, COSEM N5 and precomputed metadata by hand: cellmap-flow (image_data_interface.py plus io/, 2.7k lines), cellmap-analyze (765), mesh-n-bone (346), chunkmirage (tensorstore_source.py, 649), CineMap (slice_loader.py), liconn-err (dataset.py) and registration-station (zarr-python, by hand); salamander's analysis scripts parse OME multiscales by hand three more times. They disagree on the one rule that matters, the half voxel between a stored corner and a stored centre: all of them place an OME translation at voxel 0's centre, but mesh-n-bone also reads funlib's offset and precomputed's voxel_offset as centres (both store the corner) and ignores COSEM translate and downsamplingFactors, CineMap's extent_nm() and c-elegans' camera code treat the translation as a corner while their reads treat it as the centre, cellmap-flow learned the OME rule in PR #103 after shipping without it (salamander's predictions were half a voxel off until then), and chunkmirage's TypeScript twin handles N5 differently from its Python.

    funlib.persistence has the right vocabulary but the wrong backend for these consumers. What its Array lacks, per cellmap-flow's session: tensorstore (s3, gs and http throughput, the precomputed and zarr v3 drivers; Array reads through zarr-python and dask, and a dask scheduler has no place in a per-chunk model server); reads that run past the array and come back padded (Array.__getitem__ raises on a Roi outside the data; model halos at a volume's edge need the padding); level selection by target voxel size with an explicit mismatch policy; the OME centre rule (funlib's Roi offset is a corner); per-read retries and one shared, capped tensorstore context. Add the zarr-python major-version split across the repos (cellmap-flow pins 2.18.4; cellmap-analyze and mesh-n-bone pin >= 3.0.8; cellmap-analyze dropped funlib.persistence in 2026-04 because it lacked zarr v3), the integer-only Coordinate, and pymongo, psycopg2 and dask as dependencies of a reader. Nothing outside Janelia fills the niche: webknossos-libs, neu-vol, cloud-volume, brainhops, yaozarrs and xarray-tensorstore were all checked on 2026-10-21 and each is a pipeline or a different model, not this dependency.

    So: one small package, one class that serves both kinds of consumer, one written rule for the half voxel, and conformance tests the TypeScript side can run too.

    The write side has the same disease in a smaller body. Measured on 2026-10-22: five repos generate OME multiscales documents by hand (cellmap-analyze, mesh-n-bone, cellmap-flow, registration-station, chunkmirage; 440 lines between them), five create placed arrays with five different answers to "it already exists" (an unverified adopt zeroed 180 rows of a registration-station field), four encode chunk keys, and every write-side bug their sessions could name was a metadata bug: a scale factor that ignored the corner (cellmap-analyze #93), a level translation that ignored the ROI origin (mesh-n-bone, on master), OME 0.4 attributes inside zarr v3 groups (two repos), a hard-coded nanometre, a funlib offset holding a centre. The bytes were never the problem: they go through tensorstore or zarr-python and nobody reported a byte-level bug. So 0.2 takes the metadata and the placed creation, and nothing else of writing.

    1. Scope

    One class, WorldArray, with two faces. No legacy names: ImageDataInterface, open_ds_tensorstore and to_ndarray_ts are not in this package; each migrating repo keeps whatever shim it needs in its own subclass, for as long as it needs it.

    • Index space, native units (units=None): .ts, .meta and read_index. For chunkmirage, CineMap, liconn-err, registration-station and any tool that works in its own coordinate frame. The metadata is read exactly as chunkmirage's docs/concepts/formats.md "Stored sources" specifies.
    • World coordinates (units="nanometer" by default, or any unit per axis kind): voxel_size, translation, corner, level selection by voxel size, read of world boxes with padding, optional resampling and retries. For cellmap-flow, cellmap-analyze and mesh-n-bone, which all speak nm and Rois today, and equally for a (t, c, z, y, x) light-microscopy series or a (time, lat, lon) climate array.

    Neither face assumes microscopy or three dimensions. Any number of axes, any axis names, any units: what the store says is what the package reports, converted only on the axes it is asked to convert.

    0.1 reads. 0.2 adds the write side's metadata and placed creation (Behaviours 10 to 16): the OME document builder and the level rule, chunk keys, create, opening for write, aligned writes, add_level. 0.3 adds grids (Behaviours 17 to 19): a store-less Grid, the block iterator every blockwise repo writes for itself, write_chunk, the factor schedule and the public path helpers. Dependencies at every version: tensorstore (>=0.1.60; >=0.1.68 from 0.8, the first with file_io_locking), numpy. No zarr, no dask, no pydantic, no funlib. The package is float-only; a consumer that works in integer Rois builds them in its own subclass (section 6). Python >= 3.10 with no 3.11-only syntax, no upper bounds on numpy or tensorstore.

    The package never deletes, truncates or overwrites: there is no overwrite, delete or mode="w" anywhere in its API (Behaviour 11). What it writes is OME-NGFF zarr, v2 with OME 0.4 or v3 with OME 0.5, and nothing else (Convention 6).

    ArrayMeta is a frozen dataclass with one entry per axis, in the array's C order, and deliberately the same field names as chunkmirage's ArrayInfo: shape, dtype, chunk_shape (tensorstore's read chunk), axes (as stored; ("t","c","z","y","x")[-ndim:] when the store names none), axes_named, units (as stored, any string; "" when none), voxel_size (one index step, in units; 1.0 on unitless axes), translation (the centre of voxel 0, in units; 0.0 where the store gives none), format, path (normalised), parent, attrs and group_attrs (raw), and placed_by: which rule gave voxel_size and translation, one of ome, cosem, funlib, n5, precomputed, dimension_units, or None when nothing placed the array (then voxel size is 1 with the corner at the origin, translation 0.5, as Neuroglancer draws a plain zarr), and fill_value as the store reports it. Derived: ndim, spatial (indices of the axes named z, y or x when any are; else the last three), corner, in_units(space=, time=), in_nm(), drop_axis.

    A box for read is any of: a (begin, end) pair of float tuples in units, half-open per axis, over the spatial axes, or over every axis when it has one entry per axis (a time window and a spatial box at once); anything with .begin and .end, or .offset and .shape (so a funlib Roi works, duck-typed, without the package importing funlib); or wa.Box. Box carries funlib's Roi vocabulary on floats, half-open: shape, centre, empty, intersect, union, contains (a point or a box), grow(before, after=None), shift, snap(voxel_size, translation, mode="grow" | "shrink" | "closest") to a grid's voxel corners, to_index (the centre rule) and Box.from_index; vol.box is the array's own extent on the spatial axes, [corner, corner + shape * voxel_size), what funlib calls the array's roi; with a resample target, the target voxels shape counts, so read(vol.box) returns shape and equals Grid.from_meta(meta, voxel_size=t).box. So vol.read(vol.box.intersect(roi).snap(vol.voxel_size, vol.translation)) is the migration of a clipped, snapped Roi read, without funlib.

    There is no offset attribute anywhere in this API, because that word means the corner in funlib and the centre in OME; translation and corner are the two names for the two things. path names the array that is read: an array path is that array whatever voxel_size asks for (it resamples or relabels in place, never hops to a sibling level); only a group path chooses a level. level="first" or 0 on an array path is silently the array. There is no funlib Roi on the way out either: an integer corner-based Roi cannot hold a 10.48 nm grid, nor a 5 nm grid with translation 0 (corner -2.5), so a bridge that returned one would raise on inputs cellmap-analyze reads every day. A consumer that works in integer Rois builds them from corner, voxel_size and shape in its own subclass, where it also chooses the integer scale factor that makes the corner whole.

    shared_context(cache_bytes, threads=None) is one tensorstore.Context per budget and thread limit for the process, so the levels of a pyramid and repeat opens share one cache pool; the default budget is 0. Its decoding pool is sized by thread_budget() (0.5) and its file I/O pool by that or file_io_floor (8), whichever is larger (0.8; the argument 0.9), or both by threads when given, 0 leaving tensorstore's own sizes (0.6, Behaviour 7). capped_context is mesh-n-bone's worker-process context (every tensorstore concurrency resource limited, cache off); it returns a new context per call, as those workers inline the spec into every open today, and capped_context_spec exports the dict for callers building their own opens, writers included. Retry sizes the per-attempt timeout from the read when none is given (Behaviour 6).

    3. Conventions

    These are the rules the package exists to hold in one place. They match chunkmirage's docs/concepts/formats.md, "Stored sources", which its TypeScript twin follows too; where this document and that one differ, fix one of them.

    1. A translation is where voxel 0's centre is, as in OME-NGFF, COSEM's transform and CF coordinates. Index i on an axis sits at translation + i * voxel_size; voxel i covers [translation + (i - 1/2) * voxel_size, translation + (i + 1/2) * voxel_size). Formats that store voxel 0's corner are moved half a voxel along the spatial axes on reading. An N5 level with downsamplingFactors and no offset sits as Neuroglancer draws it, a pure scale of the base grid with every level's corner at the origin: level-L voxel i covers full-resolution voxels f*i .. f*i+f-1, so its centre is f*i + f/2 full-resolution voxels from the origin and its translation f / 2 * base. BigDataViewer centres voxel 0 on the origin instead, half a base voxel lower at every level; the shift between levels, (f - 1) / 2 base voxels, is the same in both and is the imglib2 rule liconn-err and registration-station use. (Decided 2026-10-22, when mesh-n-bone found that pixelResolution and resolution pyramids disagreed; 0.1.0 followed BigDataViewer for pixelResolution.) The shift applies only along axes named z, y or x, or the last three when axes are unnamed; never along channel or time.
    Stored Means Read as translation
    OME-NGFF translation (zarr v2/v3) centre of voxel 0 as is
    COSEM transform.translate (N5 or zarr) centre (fibsem-tools wrote it as the first sample's position; Neuroglancer ignores transform and offset on N5 entirely) as is
    funlib offset with resolution/voxel_size (N5 or zarr; offset missing = 0) corner offset + voxel_size / 2
    N5 pixelResolution or resolution x downsamplingFactors f, no offset corner at the origin at every level, as Neuroglancer draws N5 f / 2 * pixelResolution
    precomputed voxel_offset x resolution corner + resolution / 2
    CF coordinate array (xarray zarr) sample position = centre as is (chunkmirage layers this)
    nothing at all Neuroglancer draws a plain array with its corner at the origin voxels of 1, translation 0.5

    Stored numbers are never rounded onto a grid: a funlib offset of 4 at 8 nm stays 4 (cellmap-flow rounded it to 8). A group's multiscales transform for an array outranks the array's own resolution (chunkmirage's documented order), and an OME scale outranks a per-array voxel_size.

    Neuroglancer does the same, so placement by translation matches what Neuroglancer shows. Its zarr datasource (src/datasource/zarr/ome.ts, verified 2026-10-21) says: "In OME's coordinate space, the origin of a voxel is its center, while in Neuroglancer it is the 'lower' (in coordinates) corner. Translate by the physical size of half a voxel", and does so. Its precomputed datasource draws voxel i over [(voxel_offset + i), (voxel_offset + i + 1)) * resolution, whose centre is the table's (voxel_offset + 1/2) * resolution. corner is Neuroglancer's internal lower corner of voxel 0; a tool computing extents or camera positions from translation as if it were a corner is half a voxel off from the viewer.

    1. Axis order is the store's C order; N5 and precomputed are transposed to it on read, so (z, y, x) for a volume, (c, z, y, x) with channels, (t, c, z, y, x) for OME 0.5. Nothing is reordered beyond that transposition; select pins non-spatial axes. A non-zero stored origin (precomputed voxel_offset) is moved to 0 in .ts and carried in translation. \1 Sharded stores (zarr v3 sharding_indexed, sharded precomputed) read like any other through tensorstore; chunk_shape is the inner read chunk, not the shard. Unnamed axes are called ("t", "c", "z", "y", "x")[-ndim:] (chunkmirage's default) with axes_named False, so a consumer can apply its own default instead.

    2. Units are kept as stored and converted only on the axes a caller asks to convert (ArrayMeta.in_units(space=, time=), in_nm(), the units argument), through one table: for length, American and British spellings, nm, um, µm (U+00B5), μm (U+03BC), mm, cm, m, km, angstrom/Å, pm; for time, s/second, ms, us/µs, ns, minute, hour, day. Any unit string on any axis is accepted and never rejected until a conversion is asked for ("s", "m", "degrees_north", ""). A spatial axis with no unit is taken as nanometres, with a warning once per array (every repo assumed this silently; a BigDataViewer N5 whose unitless resolution is in micrometres would be read a thousandfold too small, and the warning is what tells you; base_voxel_size is the fix); an unknown unit string on an axis being converted is a ValueError, never silently the target unit; an axis not being converted keeps its string. Voxel sizes and translations are floats and are never rounded or truncated by the package: a 10.48 nm voxel stays 10.48. snap_integral is used only to absorb float noise such as 9.9999999 before comparing or ceiling.

    3. Metadata precedence per format, first match wins (chunkmirage's table):

    4. zarr v2 / v3: the OME-NGFF multiscales[0].datasets entry whose path is this array, matched by name never by position, in the parent group or, when the dataset path has more than one component ("seg/s0"), in an ancestor up to four levels above; the parent is read in both zarr formats, because a zarr v3 array inside a v2 group whose .zattrs holds the multiscales is a layout in the wild. A parent that lists levels but not this array warns, and the array is placed by its own attributes or not at all; composed with the multiscale-level coordinateTransformations when present (0.4 and 0.5; under attributes.ome in 0.5). An OME 0.6 group with coordinateSystems is read for its intrinsic system and never raises, chunkmirage's rule: take the coordinate system named by the dataset's first transformation's output, else the first system; read axes and units from it; compose only the dataset's own scale and translation, unpacking a sequence; ignore the multiscale-level transforms (they lead to other systems, which chunkmirage's scene:// applies itself) and any other transform type. Else the array's own resolution / voxel_size, offset, units, axis_names (funlib) or transform (COSEM), C order; else the same funlib keys on the parent group when the array carries none (mesh-n-bone's inputs); else tensorstore's dimension_units attribute (zarr v3). Axes from OME axes, dimension_names (zarr v3), _ARRAY_DIMENSIONS (xarray) or axis_names.
    5. N5: the array's transform (COSEM; C order unless ordering: "F"); else the parent's multiscales[].datasets[].transform for this path; else funlib's voxel_size and offset (array, else group), which zarr-python's N5 store leaves in the array's C order, read by the zarr funlib rule above; else pixelResolution (both the {dimensions, unit} form and a bare list) or resolution, from the array else the group, times the level's downsamplingFactors; plus offset; axes from the axes attribute. These lists are x-first. Without an offset the corner is at the origin at every level whichever key gave the base (BigStitcher writes resolution and downsamplingFactors; funlib writes resolution alone): translation f / 2 * base, half a voxel of the level (Convention 1).
    6. Short lists. A funlib, COSEM or N5 per-axis list shorter than the array (a 3-entry voxel_size on a (c, z, y, x) prediction, which funlib's prepare_ds(num_channels=) writes) covers the trailing axes; the leading axes get voxel size 1, translation 0, unit "" and the default axis names. OME lists must match the array exactly. A zarr offset with no voxel size places the array with voxels of 1.

    7. precomputed: resolution (nm, xyz) and voxel_offset (voxels, the corner) of the scale; levels are the scales entries in order, chosen by scale_index, by key, or by the last path segment when the path names a scale. Everything the parser did not consume stays available in attrs and group_attrs. When an array carries both an OME translation and an offset, the OME translation wins and the offset is checked against it. Two values pass silently, because both are written in the wild: offset + voxel_size / 2 == translation (funlib's prepare_ds writes the corner offset beside the centre translation on s0) and offset == translation (cellmap-analyze's create_multiscale_dataset writes the centre as offset). Anything else logs a warning naming the path and both values; it is never an error (cellmap-analyze raised on the funlib case until its PR #87 and salamander hit that). Voxel size is stricter: an OME scale and a per-array voxel_size / resolution that disagree beyond rtol 1e-6 raise ValueError, as cellmap-analyze does deliberately, because that is how stale attributes are caught and no choice between them is safe; metadata_conflicts="warn" lets a server show the image anyway, with the OME scale.

    8. Stores are read through tensorstore's kvstore only, never zarr-python: zarr.json, .zarray, .zattrs, .zgroup, attributes.json, info. Format detection probes keys in this order: zarr.json, .zarray, .zgroup, info, attributes.json, the reads begun all at once and the order deciding which document wins (0.7.1: one round trip where an http open made five in a row, cellmap-flow's measurement); when none is found, the parent is probed for info and the last path segment is taken as a precomputed scale key (mesh-n-bone's case), then s0 is probed so a group with no document of its own (an N5 directory holding s0, s1, ...) is still a group. The filesystem root, a URL's host root and a bucket root are never probed, and an ancestor that answers anything but a document (a server root's 301) ends the search for a multiscales entry quietly. Off Google Cloud, GCE_METADATA_ROOT is pointed at a name that fails at once before the first gs:// open, because tensorstore's probe of the GCE metadata server otherwise stalls every open for seconds; "off Google Cloud" is decided with no network call, from the machine's DMI product name and the GCE_METADATA_HOST and GCE_METADATA_ROOT variables, and on a Google machine the variable is left alone so the credentials the real metadata server issues keep working (store.GUARD_GCE_METADATA turns the guard off). A precomputed:// prefix is accepted and dropped. The .n5 or .zarr suffix is never used to decide the format. A zarr v2 compressor carrying members tensorstore rejects (the checksum newer numcodecs writes for zstd) is opened without them. Access: a path with no scheme is a local file; s3:// is tried anonymously then with default credentials; gs:// with default credentials then through the bucket's public https URL (TENSORSTORE_GCS_HTTP_URL overrides); http(s)://, file://, memory:// one way. AWS_ENDPOINT_URL_S3 or AWS_ENDPOINT_URL names an S3-compatible endpoint (MinIO, moto, a mirror) and AWS_REGION or AWS_DEFAULT_REGION the region, as the AWS tools read them; TENSORSTORE_GCS_HTTP_URL is tensorstore's own redirect for gs://, and the opened-kvstore cache is keyed on it, so a process that changes it between opens reads the right host. An N5 units written once as a string is read as that unit on every axis; tensorstore is given only the array members of attributes.json, so attributes it would reject do not stop the open. The next way is tried only when the error starts PERMISSION_DENIED or UNAUTHENTICATED; the way that worked is remembered per (driver, bucket) for the process. Format probing runs all probe keys under one way before moving to the next: a bucket with listing off answers 403 for a missing key, so a 403 on one probe key counts as "missing" when another probe key was read under the same way, and only when every probe key is refused is the next way tried (see Open question 4). Metadata reads retry for about five seconds in total (max_retries 5, initial_delay 0.2s, max_delay 2s); data reads keep tensorstore's defaults plus Retry, and each document read and store open is also timed out under Retry (0.7, Behaviour 6).

    9. Writing is reading inverted, in one format. The package writes OME-NGFF zarr only: zarr v2 with OME 0.4 (.zgroup, and .zattrs holding multiscales, each entry with "version": "0.4") or zarr v3 with OME 0.5 (zarr.json with attributes.ome.version "0.5" and attributes.ome.multiscales). Never OME 0.4 inside zarr v3, which two repos write today and both Neuroglancer (ome.ts line 731 falls back to attrs.multiscales) and this reader tolerate; never N5 or precomputed, because Convention 4's N5 precedence has no unambiguous inverse and chunkmirage must write exactly the documents it serves. A written translation is voxel 0's centre, written always, zeros included; scale is the voxel size; every number is written as the float it was given, never rounded. Axes get type from their name unless told otherwise and unit on space and time axes only; a zarr v3 array's dimension_names are the axis names. No legacy document is written unless the caller passes one through attrs. Reading back what was written returns the same voxel_size, translation, axes and units with placed_by == "ome": that round trip is the test every writer repo lacked.

    4. Behaviour (each statement is a test)

    1. Index reads clip, read, pad. read_index(begin, end, padding) returns an array of shape end - begin; the part inside the data is the stored values; the rest is padding (a value) or the nearest stored voxel ("edge"). Padding is never resampled or scaled. A box entirely outside the data returns the fill without touching storage. With mask=True a boolean array of the same shape, True inside the data, is returned as well (cellmap-analyze's return_valid_mask). The result is C-contiguous in native byte order (mesh-n-bone byte-swaps big-endian stores after every read today). padding and the box are per-read arguments, never only constructor state, because one cached handle per worker serves different kinds of reads (mesh-n-bone's meshing reads blocks it has grown by one output voxel per side; its pyramid builder reads ungrown blocks). padding is the fill only. There is no context or halo argument: a caller that wants context grows its own box. transform is applied to the stored values before padding.

    2. World boxes select voxels by their centres. For a box [b, e) on an axis with voxel size s and translation t, the voxels read are i with ceil((b - t) / s) <= i < ceil((e - t) / s), after snap_integral on both quotients: a quotient within 1e-6 of a whole number of voxels is that whole number, so a centre-aligned begin that computes to k + 1e-12 is k, not k + 1. A voxel is read iff its centre lies in the box. Consequences the tests pin: a box of extent m * s returns exactly m voxels whatever its alignment; a box aligned to voxel corners (every cellmap-analyze block, every cellmap-flow Roi) maps to exactly the voxels it covers; a box aligned to voxel centres (mesh-n-bone's blocks begin at translation + k * s) maps to voxels k .. k + m - 1, also exactly, because the interval is half-open at the centres and nothing is rounded; the read of the volume's own extent [corner, corner + shape * s) is the whole array with no padding. A box aligned to neither is still well defined by the centre rule; read(..., strict=True) raises instead for callers who want to be told.

    3. Level selection (select_level, Pyramid.select, open(voxel_size=)) follows cellmap-flow's four modes plus one: floor (the level at that voxel size, else the coarsest level that is no coarser than the target on any axis, else the first), finer (as floor, but an error instead of the fallback to the first level, for callers that would rather fail than read coarser data than asked), exact (that level or ValueError listing the levels), nearest (closest on a log scale summed over axes, finer on a tie), resample (the level to resample from). Voxel sizes compare as floats with rtol 1e-6, so 10.48 is not 10. A group path without level or voxel_size raises with the level list; a level name that does not exist raises with the list; an array path, or a precomputed path naming a scale, is that array or scale under level=0 or "first" silently and warns and ignores any other level. When no level has the requested voxel_size, on_mismatch decides: "error" raises with the list; "resample" reads the level level_mode picks and resamples (Behaviour 4); "relabel" reads that level voxel for voxel and reports voxel_size as the requested size with voxel i staying voxel i: every world quantity, the translation and the corner included, scales by the ratio of the sizes (cellmap-flow's rule, which chunkmirage's server relies on), so a box of m requested voxels returns m stored voxels of the level, and source_voxel_size still reports the level's own size; "keep" reads the chosen level at its own voxel size (a level pick, nothing more). relabel and nearest are different things and both exist: one is a grid policy, the other a resampling kernel. level also takes a position, 0 or "first" for the first listed level. The pyramid an array belongs to is found through its parent's multiscales; a group without multiscales is probed for s0, s1, ....

    4. Resampling (voxel_size= with no level at it and on_mismatch="resample", or read(voxel_size=)) follows cellmap-flow's io/resample.py: the target grid's voxel 0 starts at the source corner, has ceil(n * s / t) voxels, and target voxel j is centred at corner + (j + 1/2) * t, which is source index p = (j + 1/2) * t / s - 1/2. "nearest" takes the source voxel whose extent [corner + i * s, corner + (i + 1) * s) holds the target centre: nearest neighbour as ITK defines it, and the same half-open rule as Behaviour 2. A centre on a voxel boundary, which every even whole factor produces, belongs to the upper voxel, so a factor of 2 reads source voxels 1, 3, 5, ... where a stride read 0, 2, 4, ...; the stride is a half-block bias and the change is intended. The target grid is anchored at the source corner unless anchor names another world position for a target voxel corner; passing another volume's corner reads this volume onto that volume's grid, which is what contact sites, masks and intensity statistics need (cellmap-analyze's case: an 8 nm array with translation 0 read onto a 4 nm grid with corner -2 gives 0, 1, 1, 2, 2, 3, 3, 4, where the source-anchored read gives 0, 0, 1, 1, 2, 2, 3, 3, half a voxel off). "linear" takes the block mean when t / s is a whole number >= 2; a block cut short by the end of the data is the mean of what it has (a pyramid's last block), and a block that overlaps no data is outside; else linear interpolation between the two neighbours with the border voxel repeated past the first and last centre; a whole factor with an anchor off the source grid also interpolates. Integer dtypes are rounded back to their dtype. The source voxels read are derived from the first and last target centres of the box, not from the box edges, then grown by the kernel radius (0 for nearest, 1 for linear) and clamped to the data with the border repeated; a block mean on a box aligned to the target grid needs no margin. Hence a target voxel's value depends only on its index and the source array, never on where the read starts or ends: two adjoining reads agree with one read across both (the chunk independence property, tested on boundaries at every method; cellmap-analyze's current resampler fails it). Target voxels whose centres lie outside the data get the fill (with "edge", the border voxel for nearest and linear, the last block holding data for the mean), and the mask marks them. With a resample target, shape reports the target voxels covering the data on each spatial axis. A transform (a normalisation chain) is applied to the stored values before resampling and before padding, so padding is never transformed and the output takes the transform's dtype; post_transform runs after resampling and the cast back to the stored dtype, still before padding, for a normalisation that wants the resampled block. A box entirely inside the array is returned as tensorstore's own block, without a copy, a mask or a fill, under every padding mode; the mask is built only when asked for. Measured on a 4 MiB block with the page cache warm, read_index and read cost 0.1 to 0.2 ms over a raw tensorstore read, about half of what the reader they replace cost (Tests: the benchmark script in the trial notes, not part of the suite). Block means over blocks that tile the read are one reduceat pass.

    5. No dtype heuristic. The package never decides that an array holds labels. method defaults to "nearest", which invents no values and is correct for labels and acceptable for intensities; "linear" is opt-in. cellmap-flow's subclass sets padding="edge", on_mismatch="relabel" and picks method with its own is_label_dtype rule; cellmap-analyze passes method from its interpolation_order.

    6. Retries apply to data reads and data writes, with mesh-n-bone's formula, which its tests already pin: attempt k (from 1) waits timeout * k seconds on .result(), where timeout is the given value or, when None, clamp(MiB / 16, 5, 120) for a remote store (gs://, s3://, http(s)://) and clamp(MiB / 256, 5, 30) for a local one (file, memory), MiB being the size of the in-bounds part of the read after clipping, or of the box written; between attempts the sleep is base_delay * 1.3 ** (k - 1) plus U(0, 1) seconds; at most max_attempts (default 10). Retried: TimeoutError, and a tensorstore error whose message starts with UNAVAILABLE, DEADLINE_EXCEEDED or RESOURCE_EXHAUSTED or carries an HTTP 5xx or 429. Any other error is raised at once. A timed-out tensorstore future is cancelled before the next attempt starts; a write may still land after its cancel, with the same bytes the next attempt writes. Each retry is logged as a warning naming the error's first line, or its type when the message is empty (tensorstore's timeout is TimeoutError()); when every attempt times out the TimeoutError names the operation, the path and the attempts. The policy is a per-handle attribute and a per-read and per-write argument, never only constructor state.

    Documents and opens (0.7): every metadata document read or written and every store opened is timed out and retried the same way, as an operation of no bytes (by default 5 s times the attempt, ten attempts), with tensorstore's own request retries (Convention 5) running inside each attempt. A server that accepts a connection and never answers used to hold wa.open and wa.metadata forever: cellmap-flow's picker kept a 5 s probe of its own in front of them (2026-10-23). The policy is the retries of the public call doing the reading: open, open_pyramid, create, metadata, detect and open_tensorstore, which all take it; a document read later outside such a call (a zarr v2 .zattrs read on demand, a pyramid placing its levels) waits under Retry(). Listings are not timed out, their size being unknown. The open that creates an array is (0.8, cellmap-analyze's question): its second attempt may find the array its first made before timing out, so after a timed-out attempt ALREADY_EXISTS is not an error even under exists="error", and create adopts the array only if it matches what was asked for (the comparison an adopt makes), since an identical array that appeared after our own attempt is ours. That open keeps tensorstore's "os" file locking whatever the caller's context says, as create-if-absent is a conditional write.

    The watchdog (0.5): tensorstore up to at least 0.1.85 can strand a queued task. A pool worker idle for 20 ms exits, and a task queued as it exits gets no thread while the pool counts itself full (fixed upstream in google/tensorstore ed51718085, in no release yet). The future then waits forever with no tensorstore thread alive, on a read, a write or an open. A pool limited to one thread meets it most; cellmap-analyze 0.6 hung on /nrs with data_copy and file_io at 1, and one more task on the same context woke the pool within seconds (salamander's and c-elegans' live tests, 2026-10-22, with un-kicked workers staying stuck). cellmap-analyze's read retries of June 2025 ("it sometimes hangs") worked for the same reason: each attempt is a new task. So every context the package makes (shared_context, capped_context, a rebuilt one) or opens a store on is watched, weakly: one daemon thread, started on first use, gives each live watched context's decoding and file I/O pools one no-op task every second (an in-memory array copy and a local read of a key that does not exist; no store is touched, about 0.3 ms of CPU). A stranded task then runs within about a second whoever waits on it: the package, vol.ts directly, or await, at any concurrency. The retry stays the outer net. The thread stops at exit (0.9.1): an atexit handler, which Python runs once the program's other threads are joined and before it finalizes, ends it and waits for it (at most the longest one kick takes), and no new one starts after that. Python up to 3.13 ends a daemon thread that takes the GIL back during finalization with pthread_exit, and inside a tensorstore call that aborts the process with "terminate called without an active exception" and exit 134 after all the work is done (once in six of mesh-n-bone's Linux CI runs on Python 3.12, 2026-10-26; every time when a process exits while the thread kicks flat out). Open question 14 says when the watchdog goes.

    1. Contexts. Without context, every open in the process shares shared_context(0): tensorstore's cache is off and the levels of one pyramid share one context. Its data_copy_concurrency limit is thread_budget(): the first of OMP_NUM_THREADS (dask sets 1 in every worker it spawns; a cluster job script sets its slots) and LSB_DJOB_NUMPROC (an LSF job's slots) that holds a positive integer, else the CPUs sched_getaffinity allows: the cap every other threaded library in the job already takes, as Janelia's cluster guidance asks. tensorstore alone sizes both pools to every CPU of the node, whatever the job's slots, so each of twelve dask workers in a twelve-slot job on a 96-core node could start 96 threads (0.5). A dask worker therefore runs tensorstore on one thread of each pool, which Behaviour 6's watchdog makes safe. SLURM's SLURM_CPUS_PER_TASK and SGE's NSLOTS stand in for LSB_DJOB_NUMPROC elsewhere. Ahead of them all comes WORLDARRAY_THREADS (0.9), the package's own variable, for a job script to give each worker its share of the job's cores where OMP_NUM_THREADS stays 1 for numpy and LSB_DJOB_NUMPROC counts the whole job: cellmap-analyze's prologue exports its CPUs over its worker processes, at least 1, so a worker with spare cores uses them (in a two-slot job, pools of four against one halved an 8-chunk block's time, below) and a worker per slot stays at one. A handle opened on the driver before the cluster starts is then sized in each worker by that worker's share, as a pickle carries threads=None, not a number (Behaviour 11). A value that is not a positive integer raises ValueError rather than being skipped: nothing else sets this variable, so a value worldarray cannot use is a mistake to report. Its file_io_concurrency limit is that or file_io_floor, by default context.FILE_IO_FLOOR (8), whichever is larger (0.8; the argument 0.9, 1 keeping file I/O at the budget, cellmap-analyze's choice until eight is measured on /nrs at scale): file I/O threads wait on storage rather than compute, so they take no core from the job, and one of them serialises every chunk file of a block on NFS's round trips. From one decoding thread, eight 64^3 label chunks written to NFS took 166 to 176 ms with one file I/O thread and 83 to 89 ms with four to sixteen (zarr-python 2 took 102); an 8-chunk EM read from /nrs was the same either way, decoding bound. The cap is the default because the process that passes no context is the one nobody tuned: a quick dask script over wa.open(path) is how a job came to start a thousand threads on twelve slots. One thread per pool slows one task (a 256^3 block write took 2.1 s against 1.3 s uncapped) but not a job of many workers, whose throughput its cores bound either way (four writers: 1.8 s against 1.9 s). A process that wants more threads than its job has slots, a server under bsub -n 1 say, asks for more slots or says so: shared_context(cache_bytes, threads=N) limits both pools to N, and threads=0 writes no limit, leaving tensorstore's own sizes (decided 2026-10-23, over chunkmirage's objection, once the watchdog had removed the hang risk; the argument is 0.6, at chunkmirage's request, so its server keeps one watched context per cache budget for every store it opens instead of building its own). Each set of arguments is one context for the process, made on first use and watched; threads=None and the number thread_budget() returns are two contexts, as a pickle carries None for the other process to size by its own job and a number as that number. file_io_floor sizes only the budget's pool, so with a thread count of its own it is ignored and no second context is made.

    Writes (0.8). Every context the package makes (shared_context, capped_context) sets tensorstore's file_io_sync to false and its file_io_locking mode to "none", the arguments fsync=True and locking="os" restoring tensorstore's defaults. fsync cost 6.5 ms a chunk on a local NVMe disk (8.2 against 1.5 ms for a 64^3 chunk) and nothing on NFS, whose client commits a file when it closes it; zarr-python and funlib, every writer the repos used before, never synced, so a machine crash on a local disk can lose the last seconds of chunks as it always could, and a killed process loses nothing. "os" locking takes an advisory lock on a .__lock file for every write, about 10 ms of NFS round trips a chunk (21.7 against 12.0 ms for a 64^3 label chunk on /groups; zarr-python 2 took 12.7). With "none" a whole-unit write is still atomic, a temporary file renamed into place, and only concurrent read-modify-writes of one unit lose their guarantee, which Behaviour 13 never gave (partial=True is unsafe while anything else writes the unit); a write interrupted mid-way may leave a temporary .__lock file that costs space only. tensorstore's "lockfile" mode is not the default because such a file left by a killed worker blocks every later write of its unit. Together, from one-thread workers (OMP_NUM_THREADS=1) through the default context: a 64^3 label chunk to NFS took 23 ms in 0.7 and 12.2 in 0.8, an 8-chunk label block 159 and 66.5, an 8-chunk EM block 330 and 202; to a local disk the label block took 51.5 and 4.1 ms. capped_context sets data_copy_concurrency, file_io_concurrency, gcs_request_concurrency, s3_request_concurrency and http_request_concurrency to concurrency (file_io_concurrency to file_io when given, 0.8) and the cache to cache_bytes, and returns a new context each call, so two handles never share one capped pool unless the caller passes the same object twice; a concurrency of 1 is safe under Behaviour 6's watchdog, but a read or write spanning several chunks then handles them one at a time. On /nrs, from one process alternating limits op by op (c-elegans, 2026-10-23): a one-chunk block (128^3 uint64) read in 18 to 19 ms and wrote in 51 ms at both 1 and 4. An 8-chunk block (256^3, what a downsampling step reads) read in 157 ms against 73 and wrote in 312 ms against 158 in a two-slot job, but in a one-slot job read in 147 ms against 119 and wrote in 325 ms against 302 (and that job still used 1.3 cores, LSF not pinning it). Most of the gain is a core the worker was not given, so a worker per slot, as a dask job runs, loses little at 1. Both are plain tensorstore contexts; a caller may pass its own, at construction or through reopen(context=) when a long-lived worker changes its concurrency (cellmap-analyze reopens tensorstore on every read today for that reason).

    1. Thread safety. A WorldArray may be read from several threads at once; nothing in the package holds a lock around a read. No dask anywhere.

    2. Non-spatial axes. read_index works on all axes. read takes a box over the spatial axes and keeps leading non-spatial axes whole unless select pinned them, or a box over every axis, in which case Behaviour 2's centre rule applies along each axis in that axis's converted unit (a time sample is a point too, so a window [t0, t1) in seconds reads the samples whose times lie in it). The returned array's axes are vol.axes.

    Behaviours 10 to 16 are 0.2; 17 to 19 are 0.3.

    1. Documents round-trip. ome_multiscales(axes, units, levels, version) returns the complete group attributes. Written beside arrays and read back through wa.metadata, any level reports the voxel size, translation, axes and units it was given, exactly, for OME 0.4 and 0.5, for (z, y, x), (c, z, y, x) and (t, c, z, y, x), and for levels with non-whole factors and their own translations (chunkmirage's case). The documents equal the expected documents in tests/fixtures/write.json after JSON normalisation, so chunkmirage's TypeScript builder can be held to the same output; each case also carries its resolved per-axis units and types, and the call with those gives the same document, so the TypeScript side need not reimplement the broadcasting. Units are written in OME's names: any spelling the unit table knows ("nm", "µm", "nanometre") becomes "nanometer", "micrometer" and so on (wa.units.ome_name), and a unit the table does not know is written as given, Convention 3's welcome kept. The multiscale's name, metadata and type are written when given. level_shape snaps the quotient (n - origin) / f to a whole number within 1e-6 before the ceiling, so a factor that is a ratio of float voxel sizes (0.3 / 0.1 = 2.9999999999999996, chunkmirage's case) gives 3 voxels for 9, not 4. level_placement and level_shape invert Convention 1's BigDataViewer rule and agree with Behaviour 4: the level a block mean by factor f from source voxel origin produces has voxel 0 centred at translation + voxel_size * (origin + (f - 1) / 2), and a read(voxel_size=f * s, method="linear") of the source anchored at that level's corner returns the level's values. With origin > 0 the translation moves by origin source voxels: the mesh-n-bone bug that sized levels from an aligned ROI origin but placed them from voxel 0 cannot be expressed through this API.

    2. create makes a placed level, and nothing is ever destroyed. create writes, in this order, the group document (created when absent; when present, read, the dataset entry for this level added or replaced with the datasets kept in order of voxel size, everything else kept as it was) and then the array with its chunks, shards, codecs, fill value, dimension names and attrs. The format follows the container: walking up from the level's parent, the nearest existing node decides, a .zgroup group meaning zarr v2 and OME 0.4, a zarr.json group zarr v3 and OME 0.5, an array, an N5 or a precomputed node a ValueError; a format that contradicts it raises rather than mixing versions. When no ancestor exists, the walk ends at the nearest ancestor named *.zarr, the store root, format or zarr v3 decides, and every missing group from that root down to the level's parent gets a document, bare above the parent, so zarr-python browses the hierarchy and a level made in a zarr v2 container is zarr v2 (cellmap-analyze's prepare_ds, cellmap-flow's box_n groups); with no .zarr ancestor either, only the parent gets a document. chunks is required (alignment is the whole safety argument, so the package never picks a chunk shape); shards that are not a whole number of chunks on every axis raise. codecs defaults to zstd level 3 in the format's own dialect, what zarr-python's default zstd(level=0) means, so cellmap-analyze's, mesh-n-bone's and registration-station's outputs keep their compression; cellmap-flow's blosc stays blosc by passing it. There is no overwrite: with exists="error" any document already at path raises FileExistsError; with exists="adopt" an array whose shape, dtype, chunks, shards and placement match (placement within rtol 1e-6), and whose attributes hold every key of attrs with the value given as JSON stores it (keys not given are someone else's and not compared), is opened for writing and its dataset entry ensured, and one that differs raises ValueError listing every differing field and key with the value found and the value wanted (cellmap-flow's _refuse_another_region, registration-station's missing check, which let a shorter last band's chunk grid win a creation race). A creation that loses a race, the store reporting the array present after the probe said absent, is re-read with backoff, 5 attempts at 0.5 s * attempt, and then treated as an adopt (registration-station's shared_array, written because metadata appears late on NRS). The package deletes, truncates and follows no symlink, ever; a caller that wants a fresh array removes the old one with its own code first. Write units whose values all equal fill_value are not stored unless store_fill=True, so chunk presence stays the signal cellmap-flow's trainer and manifest read; a stored unit written so loses its key, as zarr-python's write_empty_chunks=False does, the one key a write may remove being the one it replaces. create returns a writable WorldArray; wa.open(path, mode="r+") opens an existing one with every rule of Conventions 3 to 5 unchanged, and a handle pickles by its arguments and its context's spec, so each worker process opens its own cheaply (a local path goes resolved against the working directory at open, so a worker that changes directory before unpickling, as cellmap-analyze's dask workers do, opens the same store; reopen uses it too), on the shared context when the handle had one (the same threads, and the same cache budget), else on a context rebuilt once per process from the same spec, so a capped context stays capped (mesh-n-bone's per-process cache and thread caps).

    3. Group attributes belong to everyone. The package rewrites only the multiscales list (0.4) or ome.multiscales (0.5), and within it only the dataset entry whose path is the level being created or added; other multiscales, other datasets and every other key of the group and of the array (fs, a registry record, y0/y1, anything) come back unchanged. The group's attributes before and after a create differ in that one entry, and not at all when the entry already says the same: adopting an identical array (placement within rtol 1e-6) reads the document, compares and writes nothing, so registration-station's twenty block jobs calling create(exists="adopt") on one output write the document in the first creation only. Rewriting a group document is a read-modify-write with no lock, so create and add_level of different levels in one group are called from one process at a time, the coordinator, never from block jobs; the docstrings say so. After a write the document is read again and, when this level's entry is missing because another process's write landed in between, merged and written again, up to 5 times, then RuntimeError: a lost update becomes a repair or an error where the store shows it, never a misplaced level. ensure_group_entry is this listing step on its own, public, for an array the package did not create (mesh-n-bone's symlinked s0) or one listed only after it is filled; it follows the same rules, ancestors included.

    4. Aligned writes need no coordination. write_index(begin, end, data) requires data.shape == end - begin, data.dtype == vol.dtype (no silent cast; ValueError), or data a scalar (a number or a 0-d array) that fills the box: it is converted to the dtype only when its value survives, so an integer or bool array takes whole numbers in its range and a float array any number it does not overflow, rounded to its precision (0 into uint8 is written; 300, -1, 0.5 and NaN raise), and a scalar equal to fill_value over whole units leaves them absent as an all-fill array does (cellmap-analyze writes a constant for every empty or masked-out block). The box must be a union of whole write units: every bound a multiple of write_shape on its axis or the array's end on that axis, so the clipped last unit is allowed; otherwise ValueError names the axis, the bound and the unit size. A unit written whole is one put, so writers in different processes writing different units need no lock and no ordering, which is what every writer repo does today by construction. partial=True lifts the check and does tensorstore's read-modify-write of the touched units, documented as unsafe while anything else writes the same unit (cellmap-flow's paint slabs, which it serialises itself). A write commits before the call returns, timed out and retried by Behaviour 6 (0.5; before, it was not, and a stranded write waited forever). write(box, data) maps a world box by Behaviour 2 and then calls write_index; a box reaching outside the array raises (nothing is padded on write) and voxel_size is not an argument (nothing is resampled on write).

    5. add_level is metadata plus an empty array. On a pyramid opened for writing, add_level(name, factors=, origin=) creates group/name through create with placement from level_placement over from_level (the finest listed when None) and shape from level_shape, copying dtype, chunks, shards, codecs and fill value from that level unless given, or with an explicit voxel_size and translation. The dataset entry is inserted so the list stays ordered finest to coarsest and an entry of the same name is replaced; the group's other content is untouched (Behaviour 12). It writes no voxel data: downsampling is the caller's, per block, through write_index, labels by mode and images by mean as each repo decides. exists means what it means for create.

    6. Chunk keys. chunk_key(index) is the key, relative to the array, of the write unit at index: zarr v2 indices joined by the array's dimension_separator (0.1.2); zarr v3 by the stored chunk_key_encoding, default giving c/0/1/2 with its separator and v2 giving 0.1.2; N5 2/1/0, x first; precomputed x0-x1_y0-y1_z0-z1 in the scale's voxel coordinates with voxel_offset included and the last range clipped to the shape; a sharded zarr v3 array keys its shards, so index is on the shard grid. parse_chunk_key inverts each and returns None for a key that is not a chunk (zarr.json, .zarray, attributes.json, info, a c/ key of the wrong arity). list_chunk_keys and list_chunks use the same parser. The free functions take the format and the array's facts instead of an open array, for an array served from nowhere (chunkmirage's frontends) or about to be created.

    7. Write units. write_shape is the shard shape of a sharded zarr v3 array, else the chunk shape; ArrayMeta.shard_shape is None when unsharded; chunk_shape stays the inner read chunk (Convention 2). chunks_covering(begin, end, write=True), list_chunks and chunk_key run on the write grid. A planner that sizes jobs from write_shape (registration-station's y-bands, cellmap-analyze's blocks) produces only aligned writes.

    8. Blocks tile, context grows, nothing runs. blocks(shape, block_shape, context, box, clip) yields, in C order, blocks whose write boxes [begin, end) partition [0, shape), or box (a voxel box, the grid anchored at its begin) when given, with no overlap and no gap, the last block on an axis clipped to the box. box may reach past the array on any side (a ROI rounded outward to a factor multiple, mesh-n-bone's halo mode): the write boxes tile it exactly, outside the array too. A block's read box is its write box grown by context on each side, where context is one int, one per axis, or a (before, after) pair per axis, clipped to the array (never to box, never a write box) when clip=True (the default; cellmap-analyze's create_block edge rule) and left unclipped when clip=False for a padded read_index (its neg_with_edge_pos mode, which reads past the array for fill). A block also carries at_start and at_end per axis, whether it is the first or last block on that axis, so a caller adds context at the array's far faces itself, and inner, the slices of the write box inside the read box, correct also when clip=False lets read_begin go below 0. len(blocks), blocks[b.id] (O(1)), blocks.index_of(b.begin) and b.index agree. vol.blocks() defaults block_shape to write_shape, so default blocks are aligned writes. Nothing is scheduled: the iterable and its blocks are plain, picklable records, and the iterable pickles without its blocks, so a worker takes an id. One grid per call: a consumer that writes several levels from one block derives the per-level boxes itself (mesh-n-bone's direct mode, two lines). write_chunk(index, data) writes the unit at index whole; data.shape must equal that unit's clipped shape.

    9. A Grid is a WorldArray without a store. Grid(shape, voxel_size, translation, axes, units, chunks, shards) answers box, corner, index_box, chunks_covering, write_shape and blocks exactly as a WorldArray of those facts does, and g.meta(dtype) agrees with wa.create(path, grid=g, dtype=dtype).meta in every field a grid has: shape, dtype, chunk and shard shape, axes, units, voxel size and translation (a grid has no path, format, documents or fill value), so a pipeline plans its output before anything exists. Grid.from_meta(meta, voxel_size=t) is Behaviour 4's target grid over that array: anchored at its corner with ceil(n * s / t) voxels, so a read(voxel_size=t) of the source fills it exactly, and its box is the target grid's extent, which may reach past the source's own box by less than one target voxel; this is the output grid cellmap-analyze's commands compute today in the integer frame.

    10. Schedules and helpers. level_factors(voxel_size, ratio, max_levels, stop_shape, shape) returns per level the per-axis factors, 2 on every axis whose current voxel size is within ratio of the smallest and 1 elsewhere, compounding level over level until max_levels or until the level's shape (from shape) fits within stop_shape; isotropic data gives all 2s at every level. store.join, parent and basename are the URL-aware path helpers Convention 5 already uses, made public. units.abbreviation returns the OME short form for any spelling the table knows and raises for one it does not.

    11. Reading onto a grid. vol.read_onto(grid, begin, end) returns voxels [begin, end) of a Grid's spatial axes, all of it when begin and end are None, read from this array, with exactly end - begin voxels on those axes; the array's other axes are read as read reads them (whole, or pinned by select), the open-time padding, method, retries and transform apply, and mask marks the grid voxels that held data. It is read(Box.from_index(begin, end, grid voxel size, grid translation), voxel_size=grid voxel size, anchor=grid corner), so Behaviours 2 and 4 decide every voxel: at the array's own voxel size (within level selection's rtol 1e-6) nothing is resampled, whatever the offset between the grids, and each grid voxel takes the stored voxel whose centre lies in it, never an interpolation, with method="linear" too; at any other voxel size the array is resampled onto the grid, anchored at its corner. Adjoining [begin, end) reads therefore agree with one read across both. The grid's spatial axes must be named as the array's are (ValueError otherwise), and its units are converted to the array's units. This is cellmap-analyze's per-operation grid: blocks come from one Grid, every input is read onto it, and outputs are created on it.

    7. Open questions

    1. Published mesh sets. Measured on 2026-10-21 by meshing one cube (4 nm voxels, voxel 0's corner at the origin, label at voxels 8 to 23, so world 32 to 96 nm) stored five ways and run through mesh-n-bone's own Meshify with its integration-test settings: OME translation 2 and cellmap-analyze-style (translation 2 beside offset 2) meshed at exactly 32 to 96; pure funlib (resolution + offset 0, no OME), prepare_ds-style (translation 2 beside funlib offset 0) and precomputed (voxel_offset 0) meshed at 30 to 94, half a voxel low against where Neuroglancer draws those voxels. The mesher itself is right (zmesh puts the surface on voxel faces around sample i); the error is that mesh-n-bone reads a funlib offset and a precomputed voxel_offset, both corners, as if they were the centre, and reads the array's offset before the parent's OME translation. Under this spec those three inputs move by half a voxel to match Neuroglancer. Must any published mesh set built from such input stay byte-compatible? mesh-n-bone's session knows of none and wants the change without a compatibility flag. The check script is check_placement.py in this session's scratchpad; it belongs in mesh-n-bone's tests with a tolerance below half a voxel (its coordinate test uses one whole voxel and cannot see this).
    2. CineMap's convention. Its reads follow the centre rule and match Neuroglancer; its extent_nm() treats the translation as a corner and does not. Which does CineMap follow?
    3. Listing-off S3 buckets. The probing rule in Conventions 5 is written from chunkmirage's description of the gotcha and tested offline with a fake store, not against a real bucket with listing disabled. One network test before 0.1.0 may change the rule.
    4. The network test against a non-integer-voxel OpenOrganelle volume (Tests) is not yet written; it needs the dataset chosen from the catalog.
    5. Legacy attributes on new outputs. Resolved 2026-10-23: nobody needs them, so there is no funlib_attrs. cellmap-analyze stopped writing funlib voxel_size and offset (which held the centre) in 0.6.0, whose outputs carry only the OME documents create writes. cellmap-flow writes them through funlib's own prepare_ds, offset as the corner beside an agreeing OME 0.4 translation, and is their only reader. dacapo reads funlib attributes through open_ds (ome_metadata=False by default), but nothing feeds it these outputs, and on a zarr v3 one funlib 0.7 silently reads voxel size 1 and offset 0. cellmap-data and fibsem-tools read OME only, and both pin zarr<3. funlib 0.6 and 0.7 also require integer offsets and voxel sizes, so a float helper here would either refuse placements or write numbers funlib truncates; a repo that wants the keys passes them through create(attrs=). Found on the way, outside this package: cellmap-data (main 356c3ac, image.py) takes an OME translation as voxel 0's corner, half a voxel off on every OME-correct store, and funlib's open_ome_ds puts the translation straight into its corner offset.
    6. The block iterator's shape (Behaviour 17). Resolved 2026-10-22: both sessions confirmed it. mesh-n-bone asked that box may reach past the array and that clip clips read boxes only, and derives its per-level boxes from one grid itself; cellmap-analyze asked for at_start/at_end per axis and inner, and confirmed that (before, after) pairs cover its context modes and that clip=False with a padded read_index is its edge-reading mode. All are in Behaviour 17.
    7. Sidecar attributes. Resolved 2026-10-22: registration-station keeps fs and fix_origin_um on the group through group_attrs and the part attributes (y0, y1, y0_core, y1_core, feather_vox) on the array through attrs, all known at creation; merge-on-create carries them and no attribute-update call is wanted.
    8. Creation on NRS. The adopt-with-backoff numbers in Behaviour 11 (5 attempts, 0.5 s times the attempt) are registration-station's and are tested here only against a fake store. Validate from two LSF jobs on the cluster before anyone relies on them.
    9. The codec default. Resolved 2026-10-22: cellmap-flow pins blosc explicitly (lz4 level 5 for blockwise outputs, zstd level 3 for annotation volumes) as zarr v2 compressor dicts; cellmap-analyze, mesh-n-bone and registration-station take the zstd default, which cellmap-analyze checked byte for byte against zarr-python's. No shortcut name is wanted.
    10. Sharding. Nobody writes shards today. registration-station wants them because a 2.4 GB chunk makes Neuroglancer decompress a whole band for one slice; mesh-n-bone would take them as an opt-in for v3 sources; cellmap-analyze would size blocks to shards. 0.2 offers shards= at creation and write_shape for planners and nothing more; whether that is enough is learned from the first repo that uses it. registration-station checked that a shard larger than the array is accepted and that band writes on shard edges, the clipped last band included, go through.
    11. Listing after filling. cellmap-analyze's #90 creates a level's array, fills it, and lists it last, so a crashed job never leaves a half-filled level listed. create and add_level list first. ensure_group_entry is the listing step, but a level created unlisted has its placement nowhere until it is listed, so a create(listed=False) handle, and its pickles, would carry the placement from its arguments alone. Decide whether that is worth having, or whether an unlisted level should describe itself on the array (an OME-shaped array attribute; funlib keys are out, open question 5).
    12. Per-open object-store credentials. cellmap-flow's MinIO writers open with a per-session key, secret and endpoint while the same process reads public S3 anonymously. tensorstore 0.1.85's aws_credentials takes no inline key and secret, and its endpoint and profile settings are process-wide through the environment, so those three writers stay on zarr-python and s3fs. Revisit when tensorstore takes static credentials per open.
    13. World boxes on blocks. cellmap-flow reads its input at one voxel size by a world box grown by a context in nanometres and writes at another; blocks (0.3) gives index boxes on one grid. Grid.blocks could carry world boxes too (b.box, b.read_box as Box, a context in world units). Two lines on cellmap-flow's side today. Not planned (2026-10-22): daisy does cellmap-flow's tiling and stays; reopen if cellmap-flow drops it.
    14. When the watchdog goes. Behaviour 6's watchdog works around tensorstore's lost wakeup, fixed upstream in google/tensorstore ed51718085 (2026-09-30, "Fix lost wakeups in TaskGroup when workers block or exit") and in no release up to 0.1.85. When a release contains it (gh api repos/google/tensorstore/compare/ed51718085...vX.Y.Z reports "ahead" or "identical"), confirm it with WORLDARRAY_STRESS=1 pytest tests/test_lost_wakeup.py -s (a plain context should strand nothing), require that release, remove watch, kick and the watchdog thread from context.py, and keep the write retries. That release needs Python 3.11 or later, as tensorstore has since 0.1.81, so it also ends support for 3.10.

    8. Constraints for whoever builds on this

    Branch off main, draft PRs, no "Test plan" section in PR bodies, never add Claude as git author or committer, /nrs/cellmap/data is read-only, no cluster jobs, few behavioural tests, minimal reusable code. The README is sections 1 to 5 of this file; a behaviour that is not stated here is not implemented without adding the statement first.

    Versioning. Every consumer pins a floating range and its CI installs the newest version in it within the hour of a release, so the version number says what a release can break. A patch release brings the code back to what this spec says, or reads more stores or reads them faster; it places nothing differently and adds nothing public. A minor release is anything else: it may move voxels or add API, and an entry added to, renamed in or removed from the unit table is API (wa.units.TABLE is public, and cellmap-flow exports it to its browser app behind a freshness test). Both were once shipped as patches and both turned cellmap-flow's CI red on every open PR within the hour: 0.1.1 moved offset-less N5 pyramids by half a base voxel, and 0.3.1 added kilometres. A changelog entry starts with Placement change when voxels move and Unit table change when the table does, and the release message to each consumer repeats those lines; nothing before 1.0 promises more. Consumers that cannot absorb a move between CI runs pin >=0.x,<0.(x+1).
